Projet perso

Sound React — particules audio-réactives

C'est quoi, TouchDesigner ?

TouchDesigner est un environnement de programmation visuelle par nœuds, pensé pour créer des expériences multimédias en temps réel. Plutôt que d'écrire du code qui s'exécute de haut en bas, on relie entre eux des « opérateurs » : chacun traite un flux particulier — vidéo, audio, géométrie 3D, données — et le réseau obtenu réagit en direct à ses entrées (son, capteurs, caméras, MIDI...). C'est un outil très utilisé pour les visuels génératifs, les installations interactives, le VJing et les scénographies live, car il s'appuie sur le GPU pour un rendu en temps réel.

Les opérateurs sont classés par famille : les CHOP pour les données qui varient dans le temps (son, mouvement, chiffres), les TOP pour l'image en 2D, les SOP pour la géométrie 3D, les DAT pour le texte, les tableaux et les scripts, et les COMP, des conteneurs qui regroupent tout, y compris la logique Python.

Fait notable pour un développeur : chaque opérateur expose nativement sa propre classe Python, avec sa documentation dédiée sur le wiki officiel (docs.derivative.ca) — pas de plugin ni de wrapper tiers à installer. Lire ou écrire un paramètre, créer, connecter ou supprimer un opérateur, réagir à un événement : tout passe par les mêmes objets Python documentés, du premier au dernier nœud du réseau. C'est cette cohérence qui rend un patch reproductible comme du vrai code plutôt que comme un fichier binaire figé — et c'est exactement ce qui m'a permis de construire Sound React sans jamais sauvegarder de fichier .toe : le réseau entier tient dans des scripts versionnés sur Git.

Le projet

Sound React est un visuel de particules qui réagit à la musique, créé uniquement avec des scripts Python — le code source complet est disponible sur GitHub. Il n'y a pas de fichier .toe dans le dépôt : à la place, trois scripts construisent tout le réseau — l'analyse du son, les particules sur GPU, le rendu et les effets. Un quatrième script fait l'inverse : il relit les réglages faits à la main dans TouchDesigner et les réécrit dans le code. Le visuel et ses réglages restent donc entièrement dans du Python.

Dans le code

Les trois scripts qui font tourner Sound React

audio_setup.py

Démo du script qui fait démarrer tout l'écosystème audio du projet

Je commence par charger le fichier audio et le brancher sur l'analyse : cela expose neuf valeurs en temps réel (low, mid, high, kick, snare, rhythm, smsd, fmsd, spectralCentroid), plus un cumul qui s'accumule dans le temps pour un mouvement qui ne se répète jamais. C'est le script le plus important du projet : toute la réactivité du visuel — tout ce qui bouge, pulse ou réagit à la musique — dépend directement de ce qui sort d'ici.

pop_setup.py

Démo du script qui construit le système de particules à partir de l'analyse audio

Ensuite, je construis le visuel : le signal audio brut devient une ligne de points, qui sert de source à un système de particules tournant en boucle sur le GPU. J'applique deux bruits et une torsion pour déformer le nuage, le tout piloté en direct par les valeurs issues de l'analyse. C'est l'ensemble de l'écosystème visuel du projet : chaque opérateur important est réglable, que ce soit pour modifier le comportement des particules ou la palette de couleurs du rendu — je le détaillerai prochainement.

save_settings.py

Démo du script qui fige dans le code les réglages ajustés à la main

Une fois le rendu ajusté à la main dans TouchDesigner, ce script relit mes réglages actuels et les réécrit directement dans les fichiers Python. Je repars ainsi exactement des mêmes réglages à la prochaine reconstruction.

Comment le signal circule

audiofilein1 ──┬── audiodevout1          (écoute du son)
             ├── null2 ──────────────┐  (signal audio brut)
             └── audioAnalysis ── null1 ─┼── speed1
                                          │
chopto1 ◄─────────────────────────────────┘  (le son devient des points)
  └── particle1 ── random1 ── null3 ── feedback1 ── rendu & effets
