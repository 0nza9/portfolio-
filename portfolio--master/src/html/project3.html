Développement du Site Web (et Discord)

Dans le cadre de la gestion d’un serveur Rust moddé, j’ai participé à la conception et au développement d’un dashboard web permettant de centraliser la gestion des joueurs, des avantages VIP et des interactions communautaires.

L’application repose sur un backend développé en Node.js, reposant sur Prisma ORM, permettant le stockage structuré des informations utilisateurs (identifiants Discord et Steam, statut VIP, historique d’activité, récompenses, etc.).

Un système d’authentification sécurisé via OAuth2 (Discord API) a été implémenté afin de permettre aux utilisateurs de se connecter avec leur compte Discord et d’associer automatiquement leur identité Steam, créant ainsi une liaison multi-comptes synchronisée avec le serveur de jeu.

Le Dashboard intègre plusieurs logiques

  • • Suivi automatisé du play streak journalier avec réinitialisation conditionnelle en cas d’inactivité.
  • • Gestion dynamique du statut VIP (durée, fidélité, récompenses progressives).
  • • Attribution automatisée d’avantages en jeu (priorité dans la file d’attente, bonus, permissions spécifiques).
  • • Synchronisation avec le serveur Rust pour appliquer les permissions et paramètres en temps réel.
  • • Interaction avec l’API Discord pour l’attribution de rôles et avantages communautaires sur le serveur Discord.

L’architecture combine gestion base de données relationnelle, logique algorithmique côté serveur (Node.js), automatisation de récompenses conditionnelles et communication inter-systèmes (serveur Rust ↔ base de données ↔ Discord API).

Pour le côté plus technique mais important à mentionner, deux bots distincts ont été conçus avec des responsabilités séparées pour permettre le fonctionnement du Dashboard comme convenu.

Le bot Purple gère le système de vote dynamique des maps (qui sont votées par les joueurs à chaque fois que la partie repart à zéro sur le serveur du jeu) via des interactions Discord (boutons API).

Chaque vote est pondéré en fonction de plusieurs critères stockés en base de données : statut VIP du joueur (avec bonus progressif selon le nombre de mois cumulés que la personne est abonnée à l’offre) et interactions passées.

La logique calcule dynamiquement un poids de vote basé sur ces paramètres, puis met à jour ou crée l’enregistrement correspondant via des opérations upsert Prisma afin de garantir l’idempotence et permettre la modification des votes sans duplication.

Il intègre également

  • • Un système de prévention de duplication via lock file pour éviter les instances concurrentes.
  • • Une gestion mémoire temporaire des messages traités pour éviter le double traitement.
  • • Des requêtes agrégées (groupBy) pour recalculer en temps réel les résultats pondérés.

Contrairement au bot Purple, orienté interaction utilisateur, le Bot Master fonctionne principalement en arrière-plan via des tâches planifiées, garantissant la synchronisation continue des statuts VIP, des streaks et des rôles Discord.

Un processus planifié s’exécute toutes les 15 minutes afin de

  • • Identifier les utilisateurs éligibles à des privilèges (VIP global, VIP serveur, streak ≥ 7 jours, Nitro Boost).
  • • Effectuer une requête relationnelle incluant une sous-requête sur les VIP serveur.
  • • Réunir les utilisateurs actifs devant posséder un rôle.
  • • Déclencher un service dédié (RoleSyncService) chargé d’appliquer les rôles Discord correspondants.
💻 Voir le code — Sentinel de synchronisation des rôles 
import cron from 'node-cron';
import { PrismaClient } from '@prisma/client';
import { RoleSyncService } from '../services/RoleSyncService';
const prisma = new PrismaClient();
export function scheduleRoleSync(roleSync: RoleSyncService) {
    cron.schedule('*/15 * * * *', async () => {
        console.log('[Cron] Sentinel: Starting periodic role sync...');
        const serverVipUsers = await prisma.serverStats.findMany({
            where: { isVip: true },
            select: { userId: true }
        });
        const serverVipIds = serverVipUsers.map(s => s.userId);
        const activeUsers = await prisma.user.findMany({
            where: {
                OR: [
                    { isGlobalVip: true },
                    { globalStreak: { gte: 7 } },
                    { isNitroBoosting: true },
                    { discordId: { in: serverVipIds } }
                ]
            }
        });
        console.log(`[Cron] Sentinel: Syncing ${activeUsers.length} active users...`);
        for (const user of activeUsers) {
            await roleSync.syncUser(user.discordId);
            await new Promise(r => setTimeout(r, 1000));
        }
        console.log('[Cron] Sentinel: Sync complete.');
    });
    console.log('[Cron] Role Sync Sentinel scheduled (every 15m).');
}

Ce mécanisme agit comme un système de réconciliation, garantissant que les rôles Discord reflètent toujours l’état réel en base de données, même en cas d’erreur, de redémarrage ou de désynchronisation temporaire.

Une seconde tâche planifiée s’exécute quotidiennement à minuit (timezone Europe/Paris) afin de

  • • Identifier les utilisateurs dont l’abonnement VIP global est expiré.
  • • Mettre à jour automatiquement leur statut en base de données.
  • • Déclencher immédiatement une synchronisation de rôles pour retirer les privilèges associés.
💻 Voir le code — Expiration automatique des VIP 
import cron from 'node-cron';
import { PrismaClient } from '@prisma/client';
import { RoleSyncService } from '../services/RoleSyncService';
const prisma = new PrismaClient();
export function scheduleVipExpiration(roleSync: RoleSyncService) {
    cron.schedule('0 0 * * *', async () => {
        console.log('[Cron] Checking for expired VIPs...');
        const now = new Date();
        try {
            const expiredUsers = await prisma.user.findMany({
                where: {
                    isGlobalVip: true,
                    globalVipExpiresAt: {
                        lt: now
                    }
                }
            });
            if (expiredUsers.length === 0) {
                console.log('[Cron] No expired VIPs found.');
                return;
            }
            console.log(`[Cron] Found ${expiredUsers.length} expired VIPs. Processing...`);
            for (const user of expiredUsers) {
                await prisma.user.update({
                    where: { discordId: user.discordId },
                    data: {
                        isGlobalVip: false
                    }
                });
                console.log(`[Cron] Expired VIP for ${user.username} (${user.discordId})`);
                await roleSync.syncUser(user.discordId);
            }
        } catch (error) {
            console.error('[Cron] Error processing VIP expiration:', error);
        }
    }, {
        timezone: "Europe/Paris"
    });
    console.log('[Cron] VIP Expiration job scheduled (00:00 Paris).');
}

Ce mécanisme repose sur une comparaison temporelle (globalVipExpiresAt < now) et permet une gestion automatisée du cycle de vie des abonnements sans intervention manuelle.
